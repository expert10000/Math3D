# GF-23–25: verified bundle, comparison and temporal sampling

Follow-up: [GF-26–28](graph-field-gf26-gf28-foundation-time-pathline.md) adds replacement-byte source rebase, measured desktop foundation evidence, verified bundle frames and physical pathlines. The limits below describe the GF-23–25 checkpoint.

## GF-23 — bundled-source foundation path

The GF-03 magnitude → orthogonal plane → physical line recipe now runs over either a saved analytic vector field or a verified 3D scientific bundle through the existing scientific execution broker. The bundled path reopens the three pinned components through the desktop verifier, checks the manifest, resource hashes, transfer checksums and coverage, and samples only the bounded transfer lattice. Physical trilinear interpolation uses the transfer's actual coordinates, including the rounded source positions of a 32³ preview. The result records `verified-volume-trilinear`, the three sample hashes and verified chunk/tile counts. Graphs and Explorer consume the same guarded result and provenance; neither Project nor Graph rows persist the transferred volume.

The committed `gf23-bundled-profile.math3d` fixture pins the 21×21×17 vortex scene, its line selection and the three derived operations. Tests reopen it, compute 21 rows, reject a changed transfer, changed Project source and unavailable verification, and prove cancellation cannot publish over a newer result. The existing 80³ golden vortex has an additional checked magnitude-profile oracle. The desktop gate uses a copied bundle: it saves/reopens the Graph row, changes and removes a source resource, withholds the row, restores the pinned bytes and refreshes explicitly. Source replacement with different bytes requires a new source generation and an explicit recipe rebase; restoring the originally pinned bytes is the relink supported by this gate. Nonuniform coordinate arrays and incompatible vector units are rejected. The broker caps work, result bytes, transfers and deadline.

`npx tsx scripts/benchmark-gf23-foundation.ts` measured 20 same-process runs on the 21×21×17 fixture on 2026-11-05. The existing checked slice preview had a 5.62 ms median; the verified magnitude-line preview had a 5.17 ms median. The existing checked probe had a 5.33 ms median; a probe on the already verified profile sampler had a 0.0022 ms median. The transfer is 179,928 bytes and the broker cap is 2 MiB. Observed process RSS peaks were 128.8 MiB for the slice and 131.2 MiB for the profile in this run. These are core-path measurements with process-level RSS, so they do not establish desktop first-paint latency or isolate profile memory from the process. That desktop measurement remains the release signoff task.

## GF-24 — verified two-source comparison

GF-18's existing analytic comparison remains readable. Its explicit Cartesian alignment policy now admits two verified scientific bundles when each source has identical physical axes, grid shape and component units. It rechecks each transferred volume, uses physical trilinear interpolation, reports coverage and writes an ordered two-source result. A bounded x-profile through the selected grid center records vector-difference magnitude and physical axis/unit. The saved Graph row holds a compact Project result reference and row hash; a missing, changed or unverified source withholds its values. Reopening a Project triggers desktop verification of both bundles before the row becomes current. No silent unit conversion, grid resampling or partial-coverage claim is allowed.

## GF-25 — versioned temporal sampling

GF-22 schema version 1 remains exact-frame-only. Version 2 explicitly declares linear interpolation between 2–64 pinned analytic Cartesian frames with identical axes, bounds and units. A probe returns interpolated vector, magnitude, physical time and frame IDs. A slice evaluates at most 32×32 probe points. Out-of-range times, spatial extrapolation, changed frames and unavailable values are rejected. The Explorer inspector can save the interpolation rule and inspect a bounded probe and slice after Project reopen. Scientific-bundle time frames, moving isosurfaces, pathlines and streaklines still need separate verification and solver gates.

## Evidence and remaining limits

Focused contract fixtures cover Project and Graph save/reopen, transfer checks, source lineage, stale status, numerical values, time bounds and work limits. Desktop gates cover the bundled profile, comparison Graph handoff and temporal probe/slice. Scientific-bundle source replacement with new data, cross-grid resampling and temporal trajectory semantics are not inferred by these contracts.
