# GRA-17: sampled Graph contour to Complex Analysis

The first mapping accepts one saved Graphs parametric object `x(t), y(t)` with finite values and included endpoints. It samples 16–4097 points over the stated parameter domain and maps each point to `z(t) = x(t) + i y(t)`. The destination is a versioned Complex Analysis document containing a polyline contour and the identity function `f(z) = z`. It does not infer a complex analytic function from the real Graph expressions.

The desktop Graph inspector reviews the point count, closure, endpoint gap and tolerance, largest sampled step, coordinate domain, source revision/hash and limitations. Auto closure requires the sampled endpoints to agree within `10⁻⁶ × max(real range, imaginary range, 1)`; explicit closed mode rejects a larger gap. Undefined or stationary paths are rejected. The preview is re-sampled against the same Graph document revision/hash before download or direct placement in Complex Analysis. The target carries the Graph document/object identity, source revision/hash, sample count, closure policy, mapping name and target structural hash. The source-status API distinguishes current, changed, missing and locally edited targets. The Complex workspace shows that status; when the Graph has changed, it previews old and new revisions, hashes, point counts and domains, then rechecks both documents before applying refresh. Refresh preserves the target identity only when the target is unedited and the matching Graph source is available.

The second mapping slice accepts two independent explicit `y(x)` Graph functions over their finite shared domain with included endpoints, using the first as the real coordinate and the second as the imaginary coordinate. It also accepts two imported, checksum-checked point series that represent the **real and imaginary components of the same 2D complex-grid line**. Those series must share the scene, dataset, manifest fingerprint, source hash, axis name/unit, fixed axis/index/coordinate and complete aligned x rows. A grid line uses every checked row (16–4097 points); a function pair uses the selected bounded sampling count. Mixed source kinds, missing sidecars, mismatched fixed coordinates, undefined samples and unsupported closure are rejected. Both Graph object IDs are recorded. Scientific mappings additionally record scene/dataset, source bundle locator, manifest fingerprint, both component resource checksums, varying axis/name/unit and fixed coordinate/name/unit. Desktop preview, placement, download, bundle verification and changed-source refresh reopen the original `.sscene` source, recheck both component slices, and compare them with the saved Graph point tables. Missing, changed or legacy imports without a saved locator require reimport before scientific mapping or refresh. The Complex workspace separately reports the Graph checkpoint status and whether the external bundle was verified in the current session; a historical verification is not treated as proof that the file remains current.

The desktop 3D complex-field importer selects a plane normal and coordinate, a line direction, and the remaining fixed coordinate. It extracts the real and imaginary lines from one freshly verified bundle read, then imports the pair as one undoable Graph operation. At least 16 aligned samples are required for a Complex contour. Each line retains its component checksum, locator, varying axis, plane normal/index/name/unit/coordinate, and the other fixed axis/index/name/unit/coordinate. A duplicate pair selection is rejected; a different plane or line can be imported separately. The Graphs mapping review requires both point tables to match on source, complete slice and every x coordinate. Complex preview, placement and linked bundle verification reopen the source and compare both fresh lines with the saved tables. A missing or changed component withholds verification; the saved source identity remains visible. This is a geometric contour of sampled field values, not a claim that the 3D field is holomorphic.

Use **Graphs → More → Author → Scientific field presets → Complex wave volume** to exercise this workflow without a folder picker. The pinned 41 × 41 × 17 complex bundle supports plane lines along all three axes; its default z plane produces a 41-sample pair. Preview and import the pair, select its real line in Graphs, then preview and open the contour in Complex Analysis.

The desktop importer can also save the verified 3D real/imaginary source and selected plane line as one native Project scientific-field document. Its source stores both component references, axis/shape metadata, locator, resource checksums and the line selection; it stores no field values. Opening the Project workspace rereads the complete bundle and compares both saved references before enabling paired preview or Graph import. Every preview, import and selection save rereads the bundle. A changed or missing component clears the ready pair. The workspace can import distinct plane lines, blocks a duplicate pair and saves a revised selection back to Project. Android editing remains deferred.

Sampling is bounded and does not establish path smoothness, winding, enclosure, analyticity or convergence of contour integrals. A narrow unsampled excursion or singularity may be missed, and the target sets winding to unknown. The mapping is geometry only, with identity `f(z)=z`; it does not turn an arbitrary sampled complex field into an analytic function. Refresh replaces the active Complex adapter checkpoint after explicit review; its earlier edit undo stack does not carry across that replacement. Export a Project snapshot before refresh if the earlier target must remain recoverable. Mobile project explorer displays a read-only linked Complex contour summary, Graph checkpoint status and scientific axes. It explicitly says the external bundle is not checked on mobile. Mobile Complex editing and physical-device/accessibility signoff remain open.

Acceptance includes a circle round trip through Complex Analysis serialization, changed/missing-source and edited-target diagnostics, undefined/closure/degenerate rejection, retained open closure across refresh, and desktop preview/download/place/change/review/refresh/Project-save/reopen/add-another journeys. The second slice adds exact paired-function tests, changed-pair refresh, verified real/imaginary grid provenance, mismatched-grid rejection, missing sidecar refusal and desktop paired-source interaction. Live-bundle tests cover matching, changed and missing sources; mobile project tests cover the read-only contour summary.

The 3D pair has core regression coverage for provenance serialization, mismatched planes, changed and missing bundles, plus an Electron import-to-Complex journey that mutates and removes a component between checks. Android remains deferred.

The saved workspace has Project serialization and validator tests, plus a desktop Project save/reopen journey covering both resource checks, retained coordinates, distinct and duplicate line imports, changed bytes and a missing component.
