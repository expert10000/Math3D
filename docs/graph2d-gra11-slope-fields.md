# GRA-11.1: bounded slope fields

Graphs supports a source object for first-order equations of the form `dy/dx = f(x,y)`. In the desktop and web Graphs workspace, choose **Add slope field** in the Functions panel, enter the right-hand expression and finite x/y bounds, then save. The mobile Graphs object chooser also exposes **slope-field** with the same equation and bounds. The field can be edited, hidden, duplicated, reordered, deleted, saved in a Graphs document and exported through the existing graph publication path. The desktop/web Inspector identifies its source and bounded direction-grid method.

The source expression uses the existing Graphs parser with coordinates `x` and `y` plus document parameters. A distinct `graph2d.slope-field.v1` capability keeps old documents unchanged. Saved expressions carry the validated AST; document compatibility and source identity use the existing Graphs contracts. A parameter named `y` cannot coexist with a slope field because `y` is its coordinate.

Sampling intersects the authored x/y bounds with the visible viewport. A grid at roughly 48-pixel spacing evaluates at most 400 centers, subject to the scene sample and deadline budgets. Each finite value produces a short line segment whose world slope is `f(x,y)` and whose screen length is bounded. Domain failures produce gaps and counted diagnostics. The field is available on linear axes; logarithmic axes yield no direction glyphs. Glyphs cannot be probed as solution points. They do not define an integral curve or initial-value solution.

Reference checks cover `y'=0` (horizontal segments), `y'=x` (segment slope at each center), singular `y'=1/x`, source persistence/capability, the grid budget and prevention of false solution probes. Browser authoring/rendering passes in two locales; mobile authoring, undo, round-trip and projection pass in software tests. Physical mobile visual and accessibility checks remain open. Follow-on GRA-11 work should define a numerical initial-value solver, error control, stopping rules at poles and viewport boundaries, and solution provenance before adding trajectories or phase portraits.
