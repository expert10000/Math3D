# GRA-12.2 — regression performance and cancellation

**Software scope, 2026-10-17.** Desktop and web Graphs run checked linear, quadratic and cubic point-series regression in a module worker. **Fit dataset** shows a pending state and **Cancel fit** terminates the worker. A new request supersedes an older one; changing the selected source, model or document generation invalidates an in-flight response. Worker errors, unreadable replies and a 15-second deadline end the request without publishing a partial fit. Cancelling retains the previous result, which remains subject to the existing source/model staleness check. This reuses the Graphs worker pattern and leaves the shared numerical model unchanged.

The regression performance test fits each reviewed model on the same checksum-verified 10,000-row table. Its conservative 5,000 ms aggregate guard covers core computation on CI; it is not a UI latency target or a device-wide promise. On the local Intel Core i7-8750H (12 logical processors), one Vitest run measured 183 ms linear, 173 ms quadratic and 152 ms cubic, or 509 ms total. These figures exclude worker creation, structured cloning and rendering. The browser test verifies termination of a pending worker and a successful subsequent real fit. Existing regression tests retain the numerical and publication assertions.

**Gallery example.** Graphs → Gallery → All scenes → Piecewise and data → **10,000-point regression** opens the identical deterministic 10,000-row benchmark corpus. Search for “regression” to find it directly. Select **10,000 measurements** in the Functions panel, then choose linear, quadratic or cubic under Inspector → Regression fitting and press **Fit dataset**. The checksum-verified original rows feed the fit. The line plot uses at most 1,024 representative rows and is labelled *downsampled*; a fitted result reports `n=10000`. This example is available in the shared desktop and mobile gallery. It does not expand the 10,000-row or 1 MiB point-table budgets.

## GRA-12.4 — mobile large-data follow-up

Mobile continues to use the bounded shared core synchronously; it does not yet offer mid-fit cancellation. This 2026-10-17 slice permits the 10,000-row connected series through its bounded mobile sampler, caches verified immutable sidecars for redraws and fitting, and reuses already validated frozen catalog presets at launch. The Gallery search keeps its content visible while the Android keyboard opens, and the canvas distinguishes a deliberately downsampled plot from a missing point table. The bundled Android app opened and plotted the 10,000-point example on the EnterpriseAnalytics_Pixel emulator; this is visual smoke evidence, not a measured latency threshold. Physical Samsung latency and the wider MOB-G13/G2D40 accessibility/device matrix remain pending. A future fit family needs its own numerical reference corpus and performance budget.
