# GF-26–28: source rebase, verified time frames, physical pathlines

## GF-26 — foundation signoff and explicit source rebase

Field Explorer now offers **Choose replacement and rebase recipes** for a saved scientific vector source with derived operations. The user chooses another `.sscene`; the desktop bridge verifies its resources and bounded three-component transfer before committing. The replacement must have different resource bytes and the same Cartesian axes and component units. `rebaseProjectDerivedSource` advances the vector source and each affected derived operation generation in topological order, retaining their IDs, parameters and physical selection coordinates. It repins only selections that referred to the exact old generation. A saved Graph profile remains withheld until an explicit refresh updates its row. A failed verification leaves the Project untouched.

The [desktop measurement](evidence/gf26-desktop-foundation-2026-11-05.json) ran three fresh Electron processes on the 21×21×17 vortex bundle, sampling `app.getAppMetrics()` every 50 ms. Median first preview was 1,696 ms for the current Explorer 3D view and 2,441 ms for the GF-23 Graph profile handoff. Median interaction was 895 ms for a verified slice-coordinate preview and 1,815 ms for an explicit Graph profile refresh after Project reopen. Median sampled process working-set peaks were 833 and 870 MiB for first preview, and 869 and 887 MiB for interaction, respectively. These are workflow measurements on this PC: Graph handoff includes navigation and source reopening, and process working set includes Electron and other app modules. They do not isolate the profile algorithm. The earlier core-path profile benchmark remains the algorithm comparison. No source transfer or broker budget was relaxed.

The desktop gate imports a saved Project, opens the profile Graph row, saves/reopens, samples a scientific time source, saves a pathline, chooses different replacement bundle bytes, observes the old temporal source and Graph row withheld, explicitly refreshes the Graph row, and repeats save/reopen and refresh. The 80³ golden numerical profile, grid-edge, incompatible-unit, cancellation and bounded-memory fixtures remain part of the GF-23 evidence.

## GF-27 — verified scientific time sources

Temporal source schema version 3 pins 2–4 scientific-bundle vector frames with linear interpolation and identical Cartesian axes, transfer grids, component units and physical time unit. Creation requires verified transfers. Saved Project metadata contains only frame document generations and time coordinates, never volume arrays. Reopening withholds values until each pinned frame is freshly verified. A single frame transfer is capped at 2 MiB and the set at 4 MiB. Physical probes and at most 32×32 slice samples interpolate between verified trilinear frame values. Missing, changed, tampered, misaligned, out-of-range or outside-domain frames withhold or reject values. Versions 1 and 2 keep their exact-frame and analytic-linear behavior.

## GF-28 — physical pathlines

The temporal pathline recipe saves a physical seed and time interval, fixed RK4 method and a 2–512 step cap. The solver yields every 16 steps, observes cancellation and Project generation changes, and requires a second desktop source verification before scientific Curve publication. A Curve stores at most 513 points with physical time, source/frame lineage, step count, evaluation count, units and `time-end`, `boundary` or `unavailable` stop reason. Project reopen shows a scientific Curve as unverified until its frames are checked again; a changed or missing frame makes it stale. The generic Project Curve preview withholds scientific pathline points because it has no external-bundle verifier; Field Explorer retains their inspectable status. An analytic fixture checks the exact displacement of a linearly changing velocity, and the bundled fixture covers save/reopen, cancellation and late source change. Streaklines require a separate release-seed gate.
