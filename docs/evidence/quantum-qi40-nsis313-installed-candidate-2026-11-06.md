# QI-40 pinned NSIS 3.13 installed candidate · 2026-11-06

QI-40 and release sign-off remain open. This is the controlled follow-up to the [NSIS `System::Store` differential](quantum-qi40-nsis-store-differential-2026-11-06.md). Removing two explicit template calls did not eliminate the access violation, and both apps had reproduced it in the old `System.dll`.

## Exact candidate and embedded plug-in

The nonpublishing [both-app build 42263292904](https://github.com/expert10000/Math3D/actions/runs/42263292904) built Math3D from `bd66f7243498f924fac8bb7849231e5f000f65a3` and Theory Lab from `38842c8ca927720e9a0f39bd6a04f0e366073996`. Its Math3D installer SHA-256 is `e3f5b81318373271a11308fc1a4df67175ab40549cf81b5e0dc2db5329425fd2`; Theory Lab's is `caa7e2fbe3350382753003782b37c358b59629b2ca29759fe414ceb842ca1c2c`. The [component record](quantum-qi40-nsis313-both-embedded-components-2026-11-06.json) extracts `System.dll` from both exact installers and finds the same 30,208-byte SHA-256 `1556ee1bf1cb477124e1269b534ed81653ba71994dab7903ee3782b75acc2810`. This matches the pinned NSIS 3.13 bundle, not the 12,288-byte old plug-in. A separate [Theory Lab-only variant](quantum-qi40-nsis313-theory-only-embedded-components-2026-11-06.json) kept Math3D on the old plug-in and embedded the new one in Theory Lab, confirming the workflow override reached the intended build process.

## Installed checks

The first [12-attempt matrix](https://github.com/expert10000/Math3D/actions/runs/42265961096) passed 12/12; the second [12-attempt matrix](https://github.com/expert10000/Math3D/actions/runs/42265966512) passed 12/12. Each comprised six Theory Lab-only installs and six installs of both apps. The third [18-attempt matrix](https://github.com/expert10000/Math3D/actions/runs/42266105287) passed 18/18, adding six Math3D-only installs alongside six Theory Lab-only and six both-app installs. In total, **42/42 probes passed**, with **24 attempts installing Math3D** and **36 attempts installing Theory Lab**. The old standard control had failed 3/12 attempts, including a Math3D setup crash, but different finite samples cannot guarantee zero failure probability. All new probes bound to build run `42263292904` and its manifest hashes.

A fourth [18-attempt matrix on `windows-2022`](https://github.com/expert10000/Math3D/actions/runs/42268900243), the release workflow's runner image, also passed 18/18 with six Math3D-only, six Theory Lab-only, and six both-app attempts. Across both runner images, the same exact installers passed **60/60 probes**, including **36 Math3D installs** and **48 Theory Lab installs**. This is a bounded reliability check, not a guarantee for all user systems.

The [installed two-app UI and QEC sign-off](quantum-qi40-nsis313-both-signoff-2026-11-06.json), [1.6.0 upgrade](quantum-qi40-nsis313-both-upgrade-2026-11-06.json), and [pre-QEC rollback](quantum-qi40-nsis313-both-rollback-2026-11-06.json) all passed on those exact files. The new toolchain is a strong installer-fix candidate, but a production release build must pin it and pass the same gates before publication.

## Remaining QI-40 memory failure

The [exact-candidate installed memory run](https://github.com/expert10000/Math3D/actions/runs/42266656203) installed Math3D successfully with [verified bytes](quantum-qi40-nsis313-both-memory-installer-2026-11-06.json). Its [80-cycle trace](quantum-qi40-nsis313-both-installed-80-2026-11-06.json) returned to one canvas after each close and held WebGL context wrappers 1 → 1 and texture wrappers 5 → 5. The [budget](quantum-qi40-nsis313-both-installed-budget-2026-11-06.json) nevertheless measured **3,243,028 bytes** of late forced-GC renderer heap growth from cycle 20 to 80, above the provisional **2,097,152-byte** limit by **1,145,876 bytes**. String shallow bytes grew 2,053,796, and the largest named constructor deltas were generic arrays and objects; the trace does not identify a causal retaining path. This is a repeat of the memory gate failure on a newly built installed candidate, so QI-40 remains open independently of installer reliability.

A [residual heap path and E2E-hook ablation report](quantum-qi40-nsis313-residual-heap-2026-11-06.md) narrows the remaining investigation but also fails the same target.
