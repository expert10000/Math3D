# QI-40 certification candidate · 2026-11-05

This is a Windows source-checkout certification record for the current Theory Lab and Math3D integration. **Release freeze is not signed off.** The numbered integration roadmap ends at QI-40; this record treats its three practical slices as source/scene parity, cross-app and portable workflows, and release hardening.

## 1. Golden source and scene matrix

[`quantum-qi40-scene-matrix.json`](quantum-qi40-scene-matrix.json) is regenerated by `node scripts/quantum-release-matrix.mjs --write` and checked by `--check` after `npm run build:main`. It pins 38 independently imported bundles: 36 `quantum-scene/v1` and two narrow `quantum-scene/v2` fixtures, including the verified saved-run QWZ bands/curvature pair. Each row records source run/result hash, exact scene JSON hash, importer fingerprint, and bounded dataset/object counts. The importer verifies bundle and binary hashes; the matrix refuses changed fingerprints and unknown reader versions. The separate QWZ baseline script asserts all 441 energies and curvature samples, gap, Chern, and exact saved-run parity.

Theory Lab's current full TypeScript suite passed 255 tests with one existing skipped test; the Python worker suite passed 140 tests with five skips after creating its documented Python 3.12 environment. The test suite now uses `unittest` consistently for the repetition-code case. Its Atlas freeze previously held the pre-large-field scene schema digest: the reviewed later change raised the v1 grid-axis cap from 49 to 97 and dataset count cap from 300,000 to 1,000,000. The semantic digest and generated reconciliation report now reflect those two changes. Older strict consumers may refuse newly enlarged scenes, so reader compatibility is certified here only for current Math3D. Existing small v1 fixtures remain unchanged.

## 2. Electron workflows on this Windows source checkout

Math3D's `npm run test:quantum:release:math3d` rebuilds both main and renderer before running the pinned matrix, baseline/importer tests, and Electron flows. The fresh renderer build is essential: an older build can make a passing Electron test irrelevant to the current inspector. The flows cover QWZ curvature/bands opening, hydrogen field promotion and Project reopen, QWZ study handoff, moved portable pack reopening, changed-blob refusal, keyboard inspector tabs, actual Electron support JSON bytes, and changed-source support-export refusal.

With `QLAB_E2E_CHECKOUT` pointing to this built Theory Lab checkout, the live Q09 test passed: a real Lab run launched Math3D with the same scene bytes as manual import. The QI08 test passed the same-run two-scene study handoff into a new Project. Support bundles are redacted and re-verified at export. Math3D's support JSON carries run/result/scene identity; the Lab's carries job/run/result identity.

QI-40 remains open until the partial and blocked gates are closed and a release candidate is reviewed.

## Reproduce

In Theory Lab: `npm run setup:python`, `npm run typecheck`, `npm test`, `npm run test:worker`, `npm run build`.

In Math3D: `npm run test:quantum:release:math3d`. For the live two-app route, build both repositories, set `QLAB_E2E_CHECKOUT` to the absolute Theory Lab checkout, then run `npx playwright test tests/e2e/quantum-q09-two-app.spec.ts --reporter=list` from Math3D.
