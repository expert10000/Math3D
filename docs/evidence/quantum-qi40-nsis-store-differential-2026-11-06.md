# QI-40 NSIS `System::Store` differential · 2026-11-06

QI-40 and release sign-off remain open. This experiment followed the [current installed candidate check](quantum-qi40-current-installed-candidate-2026-11-06.md). It tested whether removing the two explicit `System::Store` calls in electron-builder's per-user `multiUser.nsh` template eliminated the intermittent installer access violation. It did not.

## Matched candidates

The nonpublishing [standard build](https://github.com/expert10000/Math3D/actions/runs/42254227636) and [without-store build](https://github.com/expert10000/Math3D/actions/runs/42253990747) used the same Math3D source branch and Theory Lab commit `38842c8ca927720e9a0f39bd6a04f0e366073996`. Both build jobs and the functional two-app installed signoff, rollback and upgrade jobs passed. The standard Theory Lab installer SHA-256 was `5acd34485c4913ed7677f15396df5ef3783cf336a4aa0cc7fd3d1a6416e8e0a5`; the modified installer SHA-256 was `cd258057fadb0009dbcbaa225663553a2cff86dd090b6cdad239c0d41bebea79`. The modification verified the pinned `app-builder-lib@26.0.12` template SHA-256 `afa9046492317e72e79e022cdb1f42edba4687ea605300bfc01c002f3106201c` before removing only `System::Store S` and `System::Store L`; the modified template SHA-256 was `6871027d1390f21c3635c847dce79b4d3a53448df33ffd2f5e535b16502b4fed`.

## Repeated installed results

The [standard 12-attempt matrix](https://github.com/expert10000/Math3D/actions/runs/42257858806) passed 9 and failed 3. A [standard failure record](quantum-qi40-standard-math-crash-42257858806.json) shows Math3D setup itself exiting `0xC0000005` in `System.dll` at offset `00001581`, before Theory Lab ran. The [modified candidate's first](https://github.com/expert10000/Math3D/actions/runs/42256720341), [second](https://github.com/expert10000/Math3D/actions/runs/42256751010), [third](https://github.com/expert10000/Math3D/actions/runs/42256754477), [fourth](https://github.com/expert10000/Math3D/actions/runs/42257779127) and [fifth](https://github.com/expert10000/Math3D/actions/runs/42258525424) current-user matrices passed 55 of 60 probes and failed 5. The [Lab-only](quantum-qi40-storeless-lab-crash-42256720341.json), [both-app](quantum-qi40-storeless-both-crash-42256751010.json) and [Math3D](quantum-qi40-storeless-math-crash-42258525424.json) failures all name `System.dll` offset `00001581`. The [12-attempt all-users matrix](https://github.com/expert10000/Math3D/actions/runs/42258749901) passed, but that sample cannot establish that install mode is the cause.

Two full-dump failures in the [fourth matrix](quantum-qi40-storeless-stackwords-crash-42257779127.json) still could not unwind an ordered stack. A bounded scan of symbolized x86 stack words consistently found `System!Call` and `KERNELBASE!lstrcpynW` tokens; these are candidate words, not validated frames. An explicit x86 debugger-mode attempt timed out on the [Math3D failure](quantum-qi40-storeless-math-crash-42258525424.json) and has been removed from the probe. Raw full dumps remained on temporary runners.

The identical crash after the direct-call removal disproves that change as a sufficient fix. Math3D and Theory Lab both failed in the shared NSIS plug-in; the fault is not confined to Theory Lab's app code. The older [electron-builder report](https://github.com/electron-userland/electron-builder/issues/7921) has the same fault offset, but it does not prove which call site or plug-in state causes these runs. Additional `System::Store` calls exist in the bundled NSIS Modern UI page templates, and their execution during the silent probe is unverified. A pinned newer NSIS toolchain is the next controlled comparison; its embedded `System.dll` bytes must be checked before interpreting install outcomes.

Component inspection of the [standard installer artifacts](https://github.com/expert10000/Math3D/actions/runs/42260109544) and [modified installer artifacts](https://github.com/expert10000/Math3D/actions/runs/42260106139) confirms all four installers embed an identical 12,288-byte `System.dll` with SHA-256 `3eb38ae99653a7dbc724132ee240f6e5c4af4bfe7c01d31d23faf373f9f2eaca`. The [standard](quantum-qi40-standard-nsis-components-2026-11-06.json) and [modified](quantum-qi40-storeless-nsis-components-2026-11-06.json) component records bind this identity to the exact installer hashes above. This establishes the shared component, not the call path or the cause of the access violation.
