# SAGE-G06 advanced ideal invariant acceptance

In **CAS → Structures → Operations**, a saved ideal offers **Ideal radical** and **Primary decomposition and associated primes** when the Docker Sage route advertises the corresponding methods. A saved quotient of a provably homogeneous ideal in a graded `QQ` polynomial ring offers **Quotient Hilbert polynomial**. The operation panel displays a cost warning, standard or expanded budget, output cap and wall-time limit. Expanded jobs require acknowledgement. Unsupported capabilities, nonhomogeneous generators, ungraded order and oversized input leave the operation unavailable with a reason.

All three requests use the versioned pinned ideal snapshot and require an explicit budget. Input is limited to two variables, three generators, degree and term caps from the chosen budget, and 128 characters per generator. The worker has a 32-component cap for primary decomposition, a per-basis entry cap, a total byte cap, and a 15 or 30 second hard wall-time kill through the existing Sage adapter. Primary decomposition checks that each returned component is primary and their intersection reconstructs the input ideal; associated primes are the radicals of these components. Radical checks containment and radical idempotence. These checks run in Sage and are labelled as reported in the Inspector; Project import checks the exact schema, pinned identities and output bounds.

Exact local Sage 9.5 fixtures: `radical(<x²,y>) = <x,y>`; `<xy> = <x> ∩ <y>` with associated primes `<x>` and `<y>`; and the standard graded quotient `QQ[x,y]/<x>` has Hilbert polynomial `1` and Krull dimension `1`. The worker also rejects missing budgets, a degree-nine input under the standard profile, excess variables, lex order and nonhomogeneous Hilbert input. The Project roundtrip fixture saves all three results for `<xy>`, reopens the serialized Project, and checks result identity, components, associated primes and Hilbert polynomial `2`.

Acceptance results (2026-11-06): local Sage 9.5 worker fixtures passed 9 tests; focused core and broker Vitest passed 79 tests. `npm run typecheck:noemit`, `npm run build:core` and the desktop Playwright gate passed. The desktop gate ran all three operations through the shared service, inspected saved results, checked standard budget propagation, exported the Project and reopened its Hilbert result in a fresh profile. Docker Desktop's Linux engine is unavailable on this machine, so live Sage 10.10 G06 comparison is open. The earlier B08 9.5/10.10 comparison is already closed in its own acceptance record.
