# QI-40: detached OrbitControls cleanup · 2026-11-06

In Three.js 0.181.2, `OrbitControls.connect()` attaches a Control-key listener to `canvas.getRootNode()`. React can detach the canvas before its passive effect cleanup runs. `controls.dispose()` then calls `getRootNode()` on the detached canvas and removes the listener from the canvas rather than the original document. A V8 retainer path showed `HTMLDocument → EventListener → bound OrbitControls → domElement → WebGL2RenderingContext` after scene close.

The standalone viewers now remove both Control-key listeners from the canvas's original document. SurfaceViewer captures its root when connected; the other affected viewers use the canvas's `ownerDocument` during disposal. The change covers Surface, Parametric Surface, Volume, Curve, Gauss map, Riemann sphere, and saved Mesh study viewers. It does not change scientific data or rendering parameters.

A rebuilt local Electron run alternated Rice–Mele bands and hydrogenic 2p density surfaces for 20 opens and closes. The [trace](quantum-qi40-orbit-controls-disposal-20-2026-11-06.json) records three baseline canvases after every close and an observed simulated WebGL context-loss event. Document event listeners after the first close were 576 and after the twentieth close 571; DOM nodes were 2,440 then 2,305. Palette-only and gallery-only control runs also had flat listener counts. These observations support removal of the document-listener accumulation.

**Memory gate remains open.** This run was built before the separate guarded Three.js texture-listener patch on `main`. Its forced-GC renderer heap rose from 26,993,868 to 32,903,524 bytes. The final heap snapshot retained 20 additional detached Three.js canvases and 20 additional WebGL context wrappers. A shortest retainer path led from a process-global Three.js DFG lighting lookup texture through its `dispose` callback to a closed renderer context. The lookup texture's callback list grew by one per scene. The subsequent [80-cycle source check](quantum-qi40-cleanup-installer-native-rollback-2026-11-06.md) found stable WebGL wrapper counts with both fixes. Raw heap snapshots stayed local because they contain paths and application data; the bounded trace is committed. GPU allocation, an acceptable memory budget, and a post-fix installed-app run remain unmeasured.

After integrating both changes, a second rebuilt [20-cycle source trace](quantum-qi40-combined-source-20-2026-11-06.json) returned to three baseline canvases, observed simulated context loss, and kept `WebGL2RenderingContext` wrappers at 2 → 2 and `WebGLTexture` wrappers at 10 → 10. Forced-GC heap was 26,927,668 → 30,545,728 bytes. This confirms the combined local build's bounded wrapper behavior, while leaving the broader heap and installed-app gates open.

The [Windows source-memory job](https://github.com/expert10000/Math3D/actions/runs/42218224479) passed 80 cycles on exact `main` commit `cd3cc5221734232d4d60055917e28ab5c4c05a7b`. That dispatched focus skipped the installer and rollback jobs; it supplies source evidence only.
