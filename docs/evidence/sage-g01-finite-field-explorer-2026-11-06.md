# SAGE-G01 finite-field explorer acceptance

The CAS → Algebra → Structures builder already saves canonical `GF(p^n)` records. Select one, open **Operations**, choose **Finite-field explorer**, and enter an element as constant-first base-`p` coefficients. The Docker Sage route executes against the pinned field revision and saves a certificate-bearing result in the Project. The Inspector exposes Elements, Frobenius, Trace / norm, Minimal polynomial, Primitive elements and Multiplication table views. It shows the actual defining polynomial returned by that runtime; the order alone does not imply a particular generator presentation.

The request is versioned and accepts only a saved finite-field target with `p^n ≤ 64`. The result parser independently reconstructs arithmetic in `GF(p)[x]` modulo the reported polynomial. It checks all enumerated elements and nonzero orders, the complete primitive list, the chosen element's orbit, trace, norm and minimal polynomial, and every table cell when `p^n ≤ 16`. Larger tables carry an explicit unavailable reason. Invalid vectors, oversized fields, a changed pinned definition, forged invariants and unsupported routes are rejected.

Acceptance fixtures use GF(7), GF(4) and GF(49). For the GF(4) generator `a`, Sage returns modulus coefficients `[1,1,1]`, orbit `a → a²`, trace and norm `1`, minimal polynomial `[1,1,1]` and order `3`. The Project roundtrip test exports a `.math3d` Project with the field and evidence and independently parses it, checking the field ID, revision, request, result and Sage version. The desktop test runs the capability-gated operation, inspects its tabs, saves the Project, starts a fresh profile and reopens the evidence.

Verified on 2026-11-06: WSL Sage 9.5 and Docker Sage 10.10 each passed all four live arithmetic tests, including invalid inputs. A live Docker `POST /run` for GF(4) also returned success with norm `1`. Both routes chose `[3,6,1]` for this GF(49) fixture and returned generator trace `1`, norm `3`; this agreement does not make the polynomial an implicit cross-runtime contract. The core/broker tests passed 67 cases, `npm run build:core` and `npm run typecheck:noemit` passed, and the desktop run/save/fresh-profile-reopen test passed. The desktop test uses a deterministic Sage response; the arithmetic fixtures themselves run on both real Sage routes.

Commands: `sage -python -m unittest service.test_finite_field_explorer -v` in WSL, `docker exec math3d-sage-worker sage -python -m unittest service.test_finite_field_explorer -v`, `npx vitest run tests/unit/sageFiniteFieldExplorer.test.ts renderer/src/services/sageOperationExecution.test.ts`, `npm run build:core`, and `npx playwright test tests/e2e/sage-finite-field-explorer-desktop.spec.ts --reporter=list`.
