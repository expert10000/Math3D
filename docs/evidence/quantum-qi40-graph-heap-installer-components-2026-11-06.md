# QI-40 Graph rollback, heap budget, and installer component comparison · 2026-11-06

These checks continue the [native rollback and source cleanup report](quantum-qi40-cleanup-installer-native-rollback-2026-11-06.md). The pinned installed candidate is `49485e816fcfc7b46d5da1634c6746a631343f8e`; the pinned pre-QEC rollback is `55a0196fe63ca16f49c97ff1aead7e41105e0ede`.

## 1. Native Project rollback

The earlier promoted QWZ Geometry Project reopened as a compatibility preview in the pre-QEC app. A source test now reproduces one cause: a Project with saved construction/script state and **two Geometry entries** is preview-only. The older Geometry editor adapter also rejects the promoted document's `source.geometry` primitives, so simply removing the second Geometry entry would not make that copy editable.

The installed follow-up uses a Rice–Mele bands **Graph2D copy** in the same retained six-scene Project. The [first Graph rollback run](https://github.com/expert10000/Math3D/actions/runs/42218695520) and its [phase report](quantum-qi40-promoted-graph-rollback-navigation-failed-42218695520.json) show that the exact candidate installed, saved the Project and promoted Graph, opened QEC, then uninstalled and installed the exact rollback build. The older app reported **“Opened supported project workspace”**, establishing that the Graph-promoted Project passed its compatibility check. The test then looked for a document button in the full Project list, while opening the Project had switched the panel to its compact document tree. This was a test navigation error.

The [corrected installed run](https://github.com/expert10000/Math3D/actions/runs/42219564141) and its [evidence JSON](quantum-qi40-promoted-graph-rollback-passed-42219564141.json) passed every phase with the exact pinned installer hashes. It reopened the same saved Project and promoted Graph ID in the pre-QEC app, navigated to the native Graph workspace, reopened all six exact-fingerprint scene references, retained the separate saved Graph, and kept the changed setting. This closes the tested Graph2D rollback path. The promoted Geometry path remains preview-only and requires its own compatibility or migration design.

## 2. Renderer heap budget

The [Windows source 80-cycle budget](quantum-qi40-windows-source-memory-budget-2026-11-06.json) and an [independent local 80-cycle budget](quantum-qi40-local-source-memory-budget-2026-11-06.json) compare forced-GC heap **after** the preview closes at cycles 20 and 80. The provisional steady-state target is at most **2 MiB growth across those 60 cycles**. Windows grew **13,554,992 bytes**; the local run grew **15,725,000 bytes**. Both miss the target. The evaluator is now part of the Windows source workflow and emits an explicit budget artifact while the separate context/texture cleanup checks remain visible.

A [fresh Windows repeat](https://github.com/expert10000/Math3D/actions/runs/42219664921) passed the 80-cycle source cleanup gate: WebGL contexts **1 → 1**, textures **5 → 5**, and zero leftover canvases. Its [budget](quantum-qi40-windows-source-budget-repeat-2026-11-06.json) still failed, with **12,299,548 bytes** of post-warmup growth and **15,321,924 bytes** of string self-size growth. The [full report](quantum-qi40-windows-source-budget-repeat-80-2026-11-06.json) preserves the per-cycle samples.

The [80-cycle heap trace](quantum-qi40-source-large-strings-80-2026-11-06.json) shows string self sizes rising **19,552,292 bytes**, accounting for most of its **20,194,368-byte** total heap increase. A [24-cycle classification trace](quantum-qi40-source-large-string-keys-24-2026-11-06.json) found 1024-character V8 previews whose keys begin with workbook session and autosave envelope fields (`version`, `format`, `payload`, `workbooks`, `stages`, `blocks`). Retainer paths include app closures and a scheduled timer. V8 truncates these string previews, so matching prefix hashes do not prove full strings are identical; the trace also cannot assign full retained sizes or establish that autosave is the sole cause. The next repair should isolate workbook autosave/journal retention from scene preview retention, then repeat the same 80-cycle budget on source and installed builds.

## 3. Shared installer fault component

The [component comparison](quantum-qi40-installer-system-dll-2026-11-06.json) extracted `$PLUGINSDIR\System.dll` from the archived Math3D and Theory Lab setup executables on a fresh Windows runner. Both contain the **same 12,288-byte binary**, SHA-256 `3eb38ae99653a7dbc724132ee240f6e5c4af4bfe7c01d31d23faf373f9f2eaca`. The [comparison run](https://github.com/expert10000/Math3D/actions/runs/42219083791) passed. Both earlier `0xC0000005` failures named this module at offset `00001581`, which narrows the shared failing component. Binary identity does not explain the trigger or prove whether the fault is inside the plugin or a caller; a matching crash dump with stack analysis is still required.

QI-40 release freeze remains withheld: the provisional heap target fails, installed source cleanup is not packaged into the archived candidate, native Geometry rollback is preview-only, and the installer access violation lacks a stack-level diagnosis.
