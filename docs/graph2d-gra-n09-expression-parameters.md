# GRA-N09: expression-driven Graphs parameters

Graphs now supports **slider parameters** and **derived parameters** in the same document. Add a derived parameter in Graphs → More → Parameters → Add expression parameter, or choose **Make … derived** for an existing parameter. For example, with slider `a = 2`, define `b = 2*a+1`; a graph expression may then use `b*x`. Desktop and mobile display the computed value next to its expression. A derived parameter has no slider and cannot be animated directly; animate an upstream slider to drive it. **Convert … to slider** changes a derived parameter back to an independent value.

The formula uses the existing bounded Graphs expression grammar: decimal numbers, `+`, `-`, `*`, `/`, `^`, parentheses, existing parameter names, constants `pi`, `e`, `tau`, and the existing one-argument Graphs functions. It cannot use graph coordinates `x`, `y`, `t`, or `theta`. Text is limited to 512 characters, the document to 16 parameters, and resolved values to finite magnitude at most `1e9`. Units remain labels; expressions do not convert units.

The shared core builds dependencies from parsed expression symbols and evaluates them in topological order regardless of display order. Unknown names, self-reference, cycles, domain failures, nonfinite results, and out-of-budget values reject the entire edit. Deleting an upstream parameter that is still referenced also rejects the edit. A derived value is saved with its expression and checked against a fresh evaluation when the document is loaded. New documents declare `graph2d.parameter-expressions.v1`; older slider-only documents keep their bytes and capability list.

Slider previews recompute all dependents without creating undo history. Apply commits the source value and all dependent values as one Graphs scene command; Cancel restores the saved document. Animation evaluates every derived parameter at each quantized frame. Plan creation checks all frames before playback or export, so a domain failure cannot leave a partial frame sequence. Playback retains the existing frame-index timing, cancellation, and stale-source rules. The frame manifest identifies the animated input; the SVG report uses the fully resolved frame document.

Software acceptance covers multi-hop and out-of-order dependencies, unknown names and cycles, domain and magnitude limits, tampered saved values, source-linked sampling, preview/commit/undo, desktop authoring, and mobile typecheck. Physical Android and iOS visual/accessibility signoff remains in the Graphs release gates.

On 2026-10-18, focused frame-export checks used three frames of `b = 2*a+1` as `a` advanced through 0, 1 and 2. The shared export builder resolved `b` to 1, 3 and 5 in the frame documents; the SVG report and CSV manifest carried the frame source hashes. The mobile publication service verified the saved and shared bytes for both formats. A desktop Electron run downloaded both files, and browser export plus frame-worker cancellation passed in both `en-US` and `pl-PL` locale configurations. Native save/share pickers and physical-device accessibility remain pending.
