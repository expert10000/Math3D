# GRA-14: separate 3D vector-field contract

This is the reviewed contract for a separate 3D vector-field document and renderer. It is **not** a new `Graph2DDocument` object kind. The delivered slice provides the versioned document, strict expression/bundle metadata validation, source-bound revision handling, live three-component bundle verification and deterministic world-space arrow samples. The desktop editor opens from Graphs → More → 3D vector field editor; a verified three-component volume also offers “Open in 3D vector editor”. The earlier 3D point-cloud/plane preview remains a separate read-only field view.

## Source and document boundary

The document format is `math3d.vector-field3d-document` version 1 with stable identity, revision and source hash. A vector source is exactly three components `(P,Q,R)` on one ordered `(x,y,z)` domain. It may be three bounded typed expressions evaluated at the same coordinates, or one scientific bundle's vector dataset. Bundle-backed components share locator, manifest fingerprint, dataset, axes and shape, while retaining each component's resource checksum; a single-component relink is invalid. Persist the reference and coordinate/unit metadata, never a partial copy of raw field values. Bundle metadata validation alone does not establish current file bytes: missing or changed sources cannot publish current arrows or trajectories.

An axis has finite ordered bounds, a nonzero span, an explicit label and unit (or an explicit dimensionless unit). Declared component units must match coordinate units per time unit. The core validator checks these declarations exactly; it does not prove the expressions dimensionally correct. Unknown or incompatible units prevent a physical-trajectory claim and are shown in the Inspector. Source, seeds, display policy and solver policy are authored state; sampled arrows, streamlines, traces and statistics are revision-bound derived artifacts.

## Sampling and interaction

The renderer samples a bounded 3D lattice for arrows, with explicit density and glyph budgets, finite-value rejection counts, camera-independent world-space direction and magnitude, and a documented magnitude scale. A zero vector is shown as a stationary sample, not an arrow with arbitrary direction. Projection and clipping are camera work; changing the camera must not recompute the field. A color legend names whether color encodes speed, a component or a user-selected scalar. A 2D slice is an exact coordinate plane with its fixed-coordinate label, not a substitute for 3D coverage.

Seeds are authored world points. A trajectory artifact records its seed, direction, solver, absolute/relative tolerances, accepted/rejected steps, maximum arc/time and explicit stop reason (`boundary`, `stationary`, `undefined`, `step-limit`, `time-limit`, `length-limit`, `cancelled` or `solver-failure`). The current solver uses bounded adaptive RK4 step doubling with a 2,048-attempt per-seed preview cap. Scientific-bundle trajectories require a fresh, complete three-component verification and use trilinear interpolation on the checked transfer lattice. Each candidate segment is checked at intermediate points for undefined values and rapid reversals; this reduces observed pole-crossing errors but is not a mathematical guarantee against every singularity. A rendered streamline is a numerical approximation; small local residuals do not certify topology, closed orbits or complete coverage. Animation changes presentation time only until a separate time-dependent source contract exists.

## Review and acceptance gates

1. Validate expression and bundle sources, common axes/shape/checksum, units, bounds and seed coordinates before document commit. Reject ambiguous axis order and mismatched component units.
2. Keep field evaluation, arrow sampling, trajectory integration and camera projection budgets independent. Cancellation and source-revision changes invalidate derived results without changing authored state.
3. Test constant, rotational, radial, zero and singular fields against independent references; test nonuniform axes, undefined samples, all stop reasons, camera rotation, saved reopen and changed/missing/relinked bundles.
4. Desktop must show provenance, units, finite-value/rejection counts, solver tolerance and status. Mobile may offer a documented slice/read-only fallback until a measured 3D renderer passes performance and accessibility checks. Physical-device and spoken-accessibility signoff are separate gates.

The implementation records ordered axes, component/time units, seeds, display and solver policy. Expression arrows come from the authored typed AST. For bundle arrows and trajectories the host reopens the source and verifies its manifest and all resource bytes; one atomic transfer contains all three bounded volume samples. Core compares each saved reference with freshly derived metadata, including axes, shape and resource checksums, then verifies every transfer checksum before use. The document is a native Project workspace entry, so its authored seeds and solver policy survive Project save, import and reopen. Neither arrows nor trajectories enter the Project snapshot. The editor retains a legacy local save, but Project reopening clears derived results and requires fresh verification before showing scientific results. Trajectory integration runs in a disposable worker; Cancel terminates it without publishing a partial artifact. The React Three Fiber viewer uses bounded line-arrow and trajectory geometry from source-bound artifacts; camera interaction does not evaluate the field again. Its viewport-level modal remains visible on resize and provides keyboard orbit/zoom/reset, focus return and status text exposed with accessibility roles. The [packaged Windows desktop acceptance run](evidence/graph3d-desktop-acceptance-2026-10-24.md) passed the 512-glyph 5-second ceiling on an Intel UHD 770 hardware WebGL renderer, with four fresh-launch medians of 123, 133, 133 and 130 ms. Unit tests now cover non-grid-aligned poles, asymmetric and outward-facing boundaries, unequal axis spacings and nonuniform decimated transfer positions. Playwright covers Project reopen, changed/missing bundle bytes, trajectory stop reports, cancellation, resize, camera, keyboard interaction and the accessible status tree. Human Narrator spoken-output signoff remains pending.

The Android Project explorer now opens a read-only 3D field viewer. Expression fields sample from the saved document; scientific fields require a user-selected local `.sscene` folder. Each Verify action re-reads `bundle.json`, `manifest.json` and every declared binary resource, checks byte lengths, SHA-256 hashes and finite values, and hands all three checked components to the core source-reference validator before any arrows appear. A failed recheck clears earlier arrows. The native renderer shows at most 512 uniformly selected arrows with stationary markers, source status and camera controls. Authored seeds and solver settings remain in the Project document but the mobile viewer does not integrate trajectories. Android device performance, folder-picker behavior and spoken accessibility still require physical-device acceptance before mobile trajectories can begin.
