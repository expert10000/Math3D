# Graph2D analysis and constructions roadmap

**Proposed follow-on, 2026-10-13.** The next Graphs release should make analysis match the selected graph kind, then add a small persistent construction model. Existing roots, intersections, Cartesian tangents, saved probes, parameter animation, regression, and Curve/Surface promotion remain the foundation. The [canonical Graph2D roadmap](math3d-graph2d-desktop-mobile-roadmap.md) owns platform sequencing and release gates; this plan starts after G2D43 and does not change delivered status.

**Implementation update — 2026-10-13:** G2D44–50 are software implemented on `main`. G2D45 adds bounded polar swept-area and arc-length results in shared core, desktop Inspector controls, mobile analysis controls, and source-linked publication data. G2D46 groups the desktop Graphs toolbar by task, keeps Fit/zoom/grid at hand, compacts secondary function-card actions, and places active Inspector results ahead of source and sampling detail. G2D47 adds the versioned, capability-gated construction intent contract and reversible kernel commands, with malformed-document, replay, save/reopen, and desktop/mobile handoff fixtures. G2D48 resolves points, tangents, and normals from exact source expressions through generation-keyed sampling jobs and shows them in desktop/mobile viewers and construction controls. G2D49 adds saved root, minimum, maximum, and pair-intersection candidates with bounded source-linked matching. G2D50 freezes [automated software acceptance](graph2d-g2d50-acceptance.md) and fixes invalid polar bounds and sampling-worker failure recovery. The existing physical-device and spoken accessibility gates remain open.

### First release boundary

Ship G2D44–46 as the first slice. It fixes wrong-kind actions, adds native polar measurements, and makes those results usable. G2D47–49 form a second slice because persistent dependencies change the portable document contract. G2D50 is the evidence gate for the second slice. The order keeps UI shortcuts from promising constructions before the source model exists.

## Polar mathematics and product rules

For a polar source \(r(\theta)\), the source domain and selected measurement interval are angular, in radians internally. The probe reports \(\theta\), signed \(r\), and Cartesian \((x,y)=(r\cos\theta,r\sin\theta)\). Degrees may be an input/display option, but conversion occurs at the UI boundary and the unit is always explicit.

- **Swept area:** \(A=\tfrac12\int_{\alpha}^{\beta}r(\theta)^2\,d\theta\). Label this as area swept with multiplicity. It is not automatically the area of the geometric union when a curve retraces or overlaps itself. If a user requests union area, that is a separate region/topology operation.
- **Path length:** \(L=\int_{\alpha}^{\beta}\sqrt{r(\theta)^2+(r'(\theta))^2}\,d\theta\). Negative radius is valid; a sign change may pass through the pole and must not be silently converted to \(|r|\) before differentiation.
- **Bounds and confidence:** Intersect requested angular bounds with the authored domain only when the UI explicitly says it is clipping; otherwise reject an out-of-domain request. Report undefined cells, numerical tolerance, evaluation count, method, estimated error, and source generation. Reuse the existing result envelope and shared bounded-job infrastructure.
- **Reference curve:** \(r=2\cos\theta\) on \([0,\pi]\) traces the circle \((x-1)^2+y^2=1\) once. At \(\theta=\pi/3\), \(r=1\) and \((x,y)=(1/2,\sqrt3/2)\). Area is \(\pi\), length is \(2\pi\). On \([0,2\pi]\), the path retraces the circle: swept area is \(2\pi\) and path length is \(4\pi\), while the geometric union area remains \(\pi\).

Numerical tests should include this analytic case, \(r=a\) over one full turn, negative-radius intervals, pole crossings, repeated turns, cusps, undefined expressions, open endpoints, and finite evaluation budgets. A polygon drawn by the sampler is never the numerical oracle.

## Construction contract to settle in G2D47

The Graph document owns construction intent: object ID, kind, ordered input references, parameter or interval anchor, style, and required capability. The kernel owns commands and revision history. A pure resolver evaluates the dependency graph against exact source generations and publishes derived geometry/results through the existing artifact/job lifecycle. The renderer only projects those outputs.

The first object kinds are `point-on-curve`, `tangent`, and `normal`; root, extremum, and intersection anchors follow in G2D49. Use source parameter identity (`x`, `t`, or `theta`) for a point on a curve, including polar points with negative radius. A numerical candidate additionally needs a bounded search interval and stable matching policy. Persist intent and references, not sampled coordinates or a frozen drawn line.

Define the lifecycle before implementation: source edit → dependent pending/stale → recomputed or unavailable; source deletion → explicit dependent handling; undo/redo → deterministic replay; export → source/result provenance. Cycles and cross-document references need explicit rejection or a reviewed relation type. Construction count, depth, evaluation, and artifact-size limits must be bounded. A result's confidence label must distinguish exact definitions from approximate numerical solutions.

**G2D47 contract now in code.** `source.constructions` is an optional `{version:1,objects:[…]}` field. Omission preserves the existing Graph document shape; presence requires `graph2d.constructions.v1`. Each object records a stable `construction_N` ID, label, display style, capability, exactly one ordered local input, and either an `x`/`t`/`theta` point anchor or a tangent/normal dependency on a point. Polar anchors retain their angle even when the evaluated radius is negative. There are no saved sampled coordinates or line segments. The source structural hash and revision advance on construction edits. Serialization and workspace handoff carry the same source intent on desktop and mobile.

The first contract permits 32 construction objects and dependency depth 16. IDs and source references must resolve inside the document; dependencies must precede consumers, and cycles are rejected. Direct authoring accepts finite anchors inside the source's authored domain, including closed endpoints. A later source edit may move the anchor outside its new domain; the intent stays saved for the G2D48 resolver to mark unavailable. Deleting a source with dependents or deleting a point with tangent/normal dependents is refused until the dependents are removed. Reversible create/update/delete actions use a typed construction-set command in the shared kernel and replay deterministically. The resolver in G2D48 must enforce the declared 12,000 evaluation and 1 MiB artifact budgets, publish against exact source generations, and surface pending/stale/unavailable states; those runtime outputs are outside the saved contract.

**G2D48 behavior now in code.** A committed explicit, parametric, or polar probe can become a persistent point; the point stores only its source ID and `x`, `t`, or `theta` anchor. Tangent and normal objects depend on that point. The shared resolver evaluates the source AST at the anchor, then estimates a local direction from bounded neighboring evaluations. Undefined points, anchors outside a changed domain, cusps, and stationary/singular parameter directions become unavailable with a reason. The readout distinguishes source-defined points from approximate line directions. Resolved points and infinite lines carry exact source generation and are clipped for each viewer; sampled paths are never their geometry source. Desktop worker publication and mobile sampling epochs discard old generations; both hide derived geometry while a parameter preview is active. Desktop Inspector and mobile Analyze controls support promotion, anchor moves, dependent lines, and ordered deletion. The resolved artifact enforces the 12,000 evaluation and 1 MiB limits. Desktop unit and Electron flows, mobile TypeScript, and desktop/mobile handoff fixtures cover this slice.

**G2D49 behavior now in code.** A complete bounded root, minimum, maximum, or pair-intersection analysis can save one candidate as a construction. The persisted anchor records source IDs, search interval, original x, a fixed matching radius, candidate ID, numerical method, residual, confidence, classification when applicable, and source generation. Candidate documents require `graph2d.constructions.candidates.v1` as well as the original construction capability; older clients can reject them before opening. Resolution reruns the bounded analysis from source expressions, accepts exactly one candidate in the matching window with the same kind or intersection classification, and otherwise marks the object unavailable. The fixed radius is at most one sixteenth of the interval width and one third of the distance to the nearest original candidate. It is a conservative local correspondence rule, not proof of mathematical identity under arbitrary source edits. Incomplete scans never publish a candidate construction as ready. Desktop and mobile Analyze controls provide explicit save actions; save/reopen, handoff, source edits, undo, and ambiguity are covered by tests. Region/measurement construction semantics remain for separate review.

## Later decisions, outside the first two slices

| Candidate | Decision rule |
| --- | --- |
| More fitting models | Extend the existing checked point-series regression only when a concrete dataset and error model justify polynomial, nonlinear, or spline fitting. |
| Curvature constructions | [G2D51](graph2d-g2d51-curvature.md) adds signed explicit curvature; [G2D52](graph2d-g2d52-polar-differential.md) adds transient polar tangent, normal, and curvature with pole/singularity handling in core, desktop, and mobile. Persistent curvature objects and parametric curvature still need derivative, singularity, and replay rules. |
| Graph → Curve/Surface | Preserve the delivered promotion workflow. Add a construction-aware snapshot only when a downstream Curve/Surface use case needs it. |
| Scientific/Python graph datasets | Design an adapter to verified, immutable scientific-scene datasets or checked point-table sidecars. Require units, coordinate meaning, hashes, provenance, bounds, and an explicit import choice. Do not execute Python in the Graph viewer or treat sampled geometry as an editable expression. Align with [Scientific Scene Runtime](scientific-scene-runtime-roadmap.md). |
| Differential equations, Fourier analysis, complex mappings | Start separate problem statements and numerical acceptance corpora after the construction release. They are distinct domain features, not prerequisites for G2D44–50. |
