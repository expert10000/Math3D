# M3D20-17c — source reliability soak

The source manifests now identify 2.0.0, but no two-hour 2.0 soak has passed. Use `node scripts/release20-rc2-soak.mjs --plan` to see the checks. On the reviewed, clean 2.0 checkout, run:

```text
node scripts/release20-rc2-soak.mjs --run <freeze-manifest> 120 <evidence-json>
```

The freeze manifest must identify the exact checkout and dependency/schema hashes. The duration is a minimum of two hours and a maximum of 24 hours. Each cycle runs Project contracts, scientific result goldens, the quantum baseline, a desktop first-use Study save/restart, hard-exit Project recovery, and a same-process navigation/memory observation lasting the requested duration. A cycle that reaches the deadline still completes all checks. The evidence JSON records the source commit, freeze manifest hash, requested and elapsed time, each check result, and any failure. The adjacent `release20-long-memory.json` records 100-action cycles, ten-action process-tree RSS and CDP V8 heap samples, renderer/GPU private bytes, page errors, and peak sampled RSS. It refuses an E2E-hooked runtime. Keep both under an ignored evidence directory so the run does not dirty its source.

The runner reviews the memory observation with `node scripts/check-release20-long-memory.mjs <memory-receipt> source <review-json>` and fails on incomplete duration, lost samples, page errors, mismatched build identity, or a source memory budget failure. The predeclared [source long-memory limits](PERFORMANCE_BUDGETS.json) are 2,048 MiB peak process-tree RSS, at most 64 MiB late-window RSS growth, 1,024 MiB peak renderer private bytes, at most 32 MiB late-window renderer-private growth, 512 MiB peak GPU-process private bytes, and at most 32 MiB late-window GPU-private growth. The preceding and final fifths of the samples define each late-window comparison. A stable GPU process ID and zero observed WebGL context-loss events are required. These are source acceptance targets based on the short-run 1,500 MiB ceiling plus headroom; they do not certify installed memory. `MATH3D_MEMORY_SOAK_SMOKE=1` runs one 100-action cycle for development; `MATH3D_MEMORY_SOAK_SMOKE_CYCLES=10` extends that diagnostic to ten cycles. Both label output `smoke` and cannot satisfy the two-hour reviewer. Installed mode fails closed until a separately frozen installed budget and exact signed package hash exist.

This is **source-build** acceptance. The same-process portion observes interactive navigation over multiple hours and samples Electron private bytes plus GPU-process RSS as native-memory indicators. It does not measure GPU allocations or forced-GC heap growth. It does not exercise the signed installer, a live Sage backend, or device stability. Keep installed results separate and bind them to the same exact candidate before RC2 sign-off.
