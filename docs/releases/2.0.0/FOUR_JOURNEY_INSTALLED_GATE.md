Before the desktop tests, the runner calls the configured Sage service `/health` and runs cusp and smooth singularity oracles for both 3D ideals and 2D polynomials through `/run`. Set the repository secret `MATH3D_RELEASE20_SAGE_SERVICE_URL` to a reachable SageMath 10.10 service endpoint built from the frozen commit. A remote endpoint must use HTTPS. The installed qualification requires the guarded bridge's `math3dSourceCommit` to match the exact candidate source commit. The job fails if the service is absent, reports an unsupported version, serves another commit, or returns wrong oracle results. It must remain available for both CAS tests; the tests deliberately redirect to an unavailable local endpoint for their offline checks.

The [Windows Sage endpoint preflight](../../../.github/workflows/release20-sage-endpoint-preflight.yml) is a manual check that needs no installer or signing inputs. Dispatch it on `main` with the full reviewed `source_commit` while the CI Sage host is active, and retain its `release20-windows-sage-oracle` receipt. A local or Linux-only health check cannot establish reachability from the GitHub-hosted Windows runner. A passing preflight proves the route at that time; the exact-candidate qualification reruns the same oracle because endpoint availability can change.

## Short-lived Sage host on Linux CI

Provision a dedicated [Cloudflare named Tunnel](https://developers.cloudflare.com/tunnel/get-started/) with a published HTTPS hostname under the project's domain. Its origin service must be `http://127.0.0.1:8768` and its connector must run only inside the manual [Sage CI host workflow](../../../.github/workflows/release20-sage-ci-host.yml). This is a Tunnel route, independent of the Cloudflare Pages production and preview deployments. Do not install a persistent connector on a local computer. The guarded bridge exposes only `/health`, `/run`, and `/cancel` under a random 256-bit path token; direct Sage remains bound to loopback. Configure the route to bypass caching and limit Cloudflare management access to release operators.

Store three GitHub repository secrets: `MATH3D_RELEASE20_SAGE_TUNNEL_TOKEN` (the named Tunnel runtime token), `MATH3D_RELEASE20_SAGE_BRIDGE_TOKEN` (64 lowercase random hex characters), and `MATH3D_RELEASE20_SAGE_SERVICE_URL` (`https://<dedicated-hostname>/<bridge-token>`). Generate the bridge token locally and pipe it and the URL to `gh secret set`; do not put either value in a shell history command, repository file, issue, PR, or chat. A Tunnel token file exists only in the ephemeral Linux runner and is mounted read only into a digest-pinned `cloudflared` container. Rotate these secrets after the release window.

Dispatch **Host SageMath 10.10 for Windows acceptance** on `main` with the full candidate source commit and a 15–180 minute hold. The workflow keeps its Tunnel and bridge scripts at reviewed `main` while building the isolated Sage worker from that exact commit, verifies the worker and public HTTPS oracle, then prints `Sage CI host ready` without printing the guarded URL. Its receipt records the source commit and worker image digest. Dispatch the Windows endpoint preflight with the same commit while the host job is running. Run installed acceptance only after its Windows oracle receipt passes, and keep the host job active through the CAS tests. Cancel the host run after acceptance if its hold has time left; the runner stops the Tunnel connector and worker. A host receipt alone does not prove Windows reachability or an installed journey.

The older `release20-local-sage-tunnel.ps1` creates a [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) for local rehearsal. Quick Tunnels have no uptime guarantee and a newly issued hostname can fail DNS resolution. This route does not provide the source-commit attestation required by the signed installed gate.

For a future publicly trusted GA candidate, provision the four Windows signing inputs described in [signing readiness](SIGNING_READINESS.md), freeze its reviewed source commit, and build one installer. Dispatch the qualification workflow with its candidate run ID, full source commit, approved installer SHA-256, and approved freeze-manifest SHA-256. The workflow checks those values independently in the integrity, fresh-install, and upgrade jobs. The final receipt requires all five installed tests, the live Sage oracle, the first-use Study, and the 1.7 upgrade and rollback to pass for the same commit and installer hash. Record the 2.0 memory deferral explicitly under the [current scope decision](RELEASE_SCOPE.md). Inspect the uploaded Playwright JSON, Sage oracle, four-journey, and qualification receipts. The self-signed RC1 pass does not transfer automatically to changed GA bytes.
