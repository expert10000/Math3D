# Hosted compute route candidate

This is a deployment recipe, **not** a hosted 2.0 acceptance receipt. The production app remains **Limited** until the exact deployed route, worker, Sage gateway, access policy, and browser journeys pass. No release binary is served through this route; desktop downloads remain direct GitHub Release assets.

## Components and trust boundaries

The Cloudflare Pages project serves `apps/web/dist`. The repository-root `functions/api/worker/[[path]].js` and `functions/api/sage-private/[[path]].js` handle only those API prefixes. The Pages build writes `dist/_routes.json` to keep static assets outside Functions. Unknown API methods and missing configuration return JSON errors, not the app shell.

The Functions forward to a separate long-lived HTTPS compute origin. The origin must terminate TLS and forward only `/api/worker/*` and `/api/sage-private/*` to `apps/web/server/worker-proxy.cjs` bound to `127.0.0.1`. Keep the Node listener and Python worker off the public interface. The edge sends a shared secret in `X-Math3D-Edge-Token`; hosted Node mode refuses to start without a secret of at least 32 characters and rejects requests without it, including OPTIONS. The origin must reject direct requests without the secret. Store the secret in the Pages project as an encrypted secret and in the backend secret store; never put it in the browser bundle or repository.

Worker calls require a valid Cloudflare Access RS256 assertion for a configured issuer and application audience. The Function verifies the signature against the issuer's JWKS and checks issuer, audience, expiration, and not-before. It passes only a SHA-256 hash of the subject to Node. Node limits each subject to ten compute POSTs per minute, keeps async job results and cancellation scoped to that subject, and forbids the global CGAL stop operation in hosted mode. The rate counter is process-local; deploy one Node process and add Cloudflare rate limiting or durable admission storage before scaling. The global compute job queue remains bounded. Access policy must admit only intended users. A missing or invalid assertion returns JSON 401 at the Function.

Sage login remains the existing access-key exchange for an HTTP-only, Secure, SameSite=Strict cookie, with a durable quota/revocation state file. The Function forwards only required cookies and request metadata; cross-origin POSTs are rejected. Sage's private gateway credential stays at the Node service. The shared edge secret protects the backend's login endpoint from direct public traffic, while Sage sessions protect gateway execution. Ensure the origin or a Cloudflare Tunnel enforces the backend secret before any other route it may serve.

## Proposed long-lived host: Hetzner Cloud

Keep Cloudflare Pages, Functions, Access, and the existing same-origin API paths. Move only the Node proxy, Python/CGAL/VTK worker, Sage gateway, and persistent Sage policy state from the temporary PC to one x86-64 Linux VPS. Run the Node proxy on loopback and connect it through a supervised Cloudflare Tunnel; no inbound compute port needs to be opened. This is a **deployment candidate**, not a purchased server, production binding, or hosted acceptance result. The separate [free-plan design](HOSTED_BACKEND_FREE_TIER_DESIGN_2026-11-26.md) remains the current temporary-PC arrangement.

Start sizing with Hetzner **CX33** (4 shared vCPU, 8 GB RAM, 80 GB NVMe) if available, then measure concurrent Sage and Mesh jobs, peak memory, and recovery time before retaining that size. Hetzner's 26 November 2026 price schedule lists **€8.49/month excluding VAT, IPv4, backups, and other extras** for CX33 in Germany or Finland; confirm stock and the checkout price in the console. Try **NBG1** (Nuremberg) first and **HEL1** (Helsinki) if availability or measured client latency favors it. Four ICMP samples from the owner's PC averaged 79 ms to NBG1 and 82 ms to HEL1; that narrow sample does not establish production latency or capacity. Keep an x86-64 image for the current native Python/CGAL dependency chain, and move to more RAM or a higher-performance plan if the workload measurements require it.

Sources checked 26 November 2026: [Hetzner locations](https://docs.hetzner.com/cloud/general/locations/), [CX33 specifications](https://www.hetzner.com/cloud/cost-optimized/), [Hetzner price schedule](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/), and [Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/concepts/). Cloudflare Workers' [128 MB memory limit](https://developers.cloudflare.com/workers/platform/limits/) is unsuitable for this native stack. Cloudflare Containers are a later alternative for bursty use, but their [default disk is ephemeral](https://developers.cloudflare.com/containers/faq/) and their [compute/storage billing](https://developers.cloudflare.com/containers/platform/pricing/) needs a separate cost and persistence design.

Before production cutover, provision the VPS and backup, reproduce the exact-source services and restricted secrets, verify service restart and a real reboot, then attach a separate preview Tunnel. Fix the worker Access sign-in/reauth path so an expired browser session does not appear only as `Failed to fetch`. Complete signed browser CGAL/Sage/VTK coverage, two-identity job isolation, quota and revocation after restart, outage recovery, and Project/source reopen. Review the current 16 MiB Pages body limit and 30-second upstream timeout for larger jobs. Bind `app.math3dlab.com` only after exact deployed-byte and security/functional receipts pass; keep the PC preview available for rollback until then.

## Required deployment inputs

1. Keep the Pages project build command `npm ci && npm --prefix renderer ci && npm run build:web:pages`, output `apps/web/dist`, and repository root as its Functions root. Verify the published deployment contains the two Functions and `/_routes.json` in its output. Set Pages encrypted secrets `MATH3D_COMPUTE_UPSTREAM_URL=https://<dedicated compute hostname>/` and `MATH3D_COMPUTE_EDGE_TOKEN=<random secret of at least 32 characters>`. Set `MATH3D_CF_ACCESS_ISSUER=https://<team>.cloudflareaccess.com` and `MATH3D_CF_ACCESS_AUD=<worker Access application AUD>` as Pages variables. The upstream URL must be HTTPS and cannot resolve back to the app hostname.
2. Configure a Cloudflare Access application for `https://app.math3dlab.com/api/worker/*` with a narrow user policy and the AUD above. Protect the immutable preview hostname too, or exercise it with a controlled signed assertion before production. Ensure browser requests reaching the Function carry the signed `Cf-Access-Jwt-Assertion` header. Keep a deployment control or rate rule that fails closed if Functions are exhausted; static SPA fallback must never authorize an API call.
3. Provision the long-lived host with this exact source revision, Python worker and its CGAL/VTK/volume dependencies, a persistent writable policy volume, and the Sage gateway service. Set `MATH3D_WEB_WORKER_PROXY_HOST=127.0.0.1`, `MATH3D_WEB_EDGE_TOKEN` to the same edge secret, `MATH3D_SAGE_WEB_AUTH_MODE=hosted`, `MATH3D_SAGE_WEB_ORIGIN=https://app.math3dlab.com`, `MATH3D_SAGE_WEB_SESSION_SECRET`, `MATH3D_SAGE_WEB_USERS_JSON`, `MATH3D_SAGE_WEB_STATE_FILE`, `MATH3D_SAGE_GATEWAY_URL`, and `MATH3D_SAGE_GATEWAY_TOKEN`. Leave `MATH3D_MOBILE_PAIR_TOKEN` unset on this dedicated hosted proxy so the edge credential is the only service credential required by the Functions. Follow [Sage gateway setup](../../../services/sage-gateway/README.md). Use one proxy process per state file.
4. Point the Pages upstream URL to that host only after the reverse proxy, TLS certificate, shared-secret rejection, worker diagnostics, and Sage gateway have passed locally. A preview that tests valid Sage sessions needs a separate backend instance with `MATH3D_SAGE_WEB_ORIGIN` set to that immutable preview origin, separate test users, policy state, and secrets. Otherwise use preview only for fail-closed denial checks and run the valid-session gate on production after deployment. The Functions have a 16 MiB request body limit and a 30-second upstream timeout; qualify any larger or longer compute workload separately.

## Acceptance before changing the platform claim

On the immutable preview deployment and then `app.math3dlab.com`, record deployed commit and byte identity; prove unauthenticated worker GET/POST and direct-origin requests deny with JSON. With an isolated preview backend, also prove authorized worker health and a real CGAL/VTK/volume operation, async job ownership/cancel, quota, and backend outage response there; otherwise run that gate on production after deployment. Prove Sage invalid key, valid session, two-user isolation, live result, quota, revocation across proxy restart, and outage recovery on production (and on preview only with a separate preview backend). Reopen a Project with resulting source after browser restart and verify external scene transport, permission denial, narrow layout, locale, and offline-after-load gates in the hosted acceptance record. Until then, keep release closure items 15–16 open and the platform matrix at **Limited**.

Local verification: `npm run test:hosted:route`, `npm run build:web:pages`, and `npx wrangler pages dev apps/web/dist --port 8788`. With Python/VTK installed, `npm run test:hosted:worker:live` executes a real VTK sphere job through the hosted Node proxy and verifies cross-user job denial. Without deployment secrets, local Wrangler returns JSON 401 for `/api/worker/diagnostics`, JSON 503 for `/api/sage-private/health`, and 200 for the static app root. These local results do not qualify live hosted compute.
