# M3D20-01a — Current Project, selection, result, resource, and job contracts

**Status:** source inventory for review, 2026-11-06. **Baseline:** `main` at `ffc4f4a6`. This records implemented contracts and known overlap; it does not define the M3D20-01b adapter API or freeze the M3D20-01d extension rules. Scope follows the [2.0 roadmap](ROADMAP.md).

## Existing overlap and partial coverage

1. **Project formats:** `Math3DProject` is the named mixed Project contract. [`serialization.ts`](../../../packages/core/src/serialization.ts) still defines `math3d.scene-project` v1 for scene/command-log handoff, and [`renderer/src/workbook/projectFormat.ts`](../../../renderer/src/workbook/projectFormat.ts) accepts Workbook bundle envelopes and older forms. These are compatibility surfaces; the 2.0 adapter must specify conversion rather than grant them independent new Project identities. The older [PRJ16 representation inventory](../../project-representation-inventory.md) is host-qualification history from October, not the schema authority for this baseline.
2. **Selection representations:** authored `ScientificSelection`, read-only vector/Graph legacy slots, Graph-local focus, and `ViewerCommittedSelection` overlap in user intent but carry different evidence and persistence rules. The [GF-01 inventory](../../graph-field-gf01-scientific-selection-contract.md) enumerates legacy slots; current code also persists authored selections. The next adapter must preserve nullable source checkpoints and explicit units instead of inferring freshness or silently turning focus into a scientific selection.
3. **Result families:** `workspace.results` is the versioned cross-module `AnalysisResultEnvelope` list. Project algebra evidence in [`projectAlgebraEvidence.ts`](../../../packages/core/src/projectAlgebraEvidence.ts) separately stores schema-checked Sage result, object revision/target hash, runtime and optional certificate; saved Mesh comparisons hold pinned result references. These have domain-specific ownership. A common result card may reference them, but migration/conversion and status mapping are not yet specified here.
4. **Scene/resource catalogs:** Project external scene references, workspace scientific scene library metadata, Graph field references, manifest resources, artifact registry bytes, and M3D Mesh resources each use their own locator/hash/availability shape. Manifest validation does not replace byte verification. M3D20-01b needs an explicit adapter mapping for `missing`, `offline`, `relinked` and `reimported` states; current hashes must not be treated as proof that bytes are available now.
5. **Job paths:** the shared scientific job/broker contracts coexist with feature worker coordinators, for example [`VolumeWorkerCoordinator`](../../../renderer/src/volume/workerCoordinator.ts), and with legacy request types in [`workerContracts.ts`](../../../packages/core/src/workerContracts.ts). The worker operation registry maps legacy kinds to canonical operation IDs. The 2.0 integration must route through existing broker/service ownership where applicable and inventory remaining feature-specific paths before replacing them.
6. **Capability layers:** platform facilities, broker operation discovery and Sage route manifests answer different questions. There is no single implemented cross-module capability-and-selection adapter registry yet; that is M3D20-01b. The [runtime architecture](../../runtime-architecture.md) and [layered workspace architecture](../../architecture-layered-workspace.md) provide context, while the source files above define this inventory's current contract claims.

## Handoff invariants for M3D20-01b/01c

- Keep `Math3DProject.identity` and each document's `DocumentIdentity` distinct. Preserve exact source generations and structural hashes across saved references, replay and handoff.
- Extend or adapt `MixedWorkspaceDocument.results`, `ScientificSelection`, resource references and `ScientificJobRequest` before proposing a parallel persistent registry, selection cursor or generic job runner.
- Treat a declared artifact, scene fingerprint or saved result as evidence metadata until its source and resource bytes are resolved and checked. Surface `stale`, `missing` and `unavailable` explicitly.
- Add compatibility fixtures for current Project/Workspace records, older scene and Workbook envelopes, legacy versus authored selections, result/artifact references, and invalid/stale source generations. Fixture scope belongs to M3D20-01c; this inventory makes no compatibility claim beyond the validators cited above.
