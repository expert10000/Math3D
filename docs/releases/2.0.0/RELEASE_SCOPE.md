## What counts as a journey

The roadmap originally defines **three flagship end-to-end journeys**: Surface, QWZ, and Algebra. The 2.0 scope adds **Field Explorer → Graph → Field** as a fourth required bounded journey. The [Guided Study Gallery](CURATED_STUDY_GALLERY.md) has **16 entry cards**, of which 12 create built-in Project copies, three require external scientific scene bundles, and one opens CAS examples. The added Volume → Mesh card is a candidate entry. The [cross-module acceptance matrix](ROADMAP.md#19-cross-module-acceptance-matrix) has **16 cases**, including Field → Graph → Field as ACC-03. These counts describe a release promise, a catalogue, and an acceptance inventory respectively; one card or passing source test is not a complete end-to-end journey.

### Four required 2.0 journeys

| Journey | Claim within 2.0 scope | Required closure evidence | Explicit limit |
| --- | --- | --- | --- |
| Surface → Curve → Mesh → comparison → Workbook | A saved Surface yields a sampled characteristic Curve and tessellated Mesh; qualified analytic and discrete curvature evidence, its source relation, Study, and Workbook citation survive reopen and transfer. | Native desktop route through the exact saved sources; valid, changed, missing, cancelled and reimported cases; mathematical truth fixture; installed-candidate journey. See closure TODO #4. | A sampled interior curvature maximum and local discrete error are not a certified continuous ridge or convergence proof. Broader Surface families require their own evidence. |
| QWZ Study → reciprocal selection → Graph → publication | Two verified producer scenes form a four-view Study. A pinned reciprocal sample links the views and a bounded producer-sample path or section becomes a source-linked Graph and evidence export. | Independently verified scene bundles; exact reciprocal frame and sample checks; source-and-back navigation, cold reopen, tampered/missing source refusal, independent package transfer, and installed-candidate journey. See TODO #5. | External producer data is required. Connecting its samples does not compute new band energies or independently certify the physical model. |
| CAS polynomial/ideal → locus → Geometry/Curve → singularities | A supported Sage operation is admitted for a current typed algebra source; exact equations and bounded real visualization remain distinct, with saved singularity evidence and offline read-only reopen. | Live qualified Sage route, valid/cancelled/offline/stale/reimported cases, exact source and output identity, and installed-candidate route availability. See TODO #6. | The demonstrated path is bounded. Unsupported singular sets and general algebraic visualization are not claimed. Sage computation is optional when no qualified route is available; saved verified bytes remain readable. |
| Field Explorer → saved line profile → Graph → exact Field return | A finite, source-linked line profile from a declared physical plane becomes a saved Graph. A selected Graph row returns to its exact Field source and position; a Project Study and Workbook cite the verified source and result. | One connected desktop journey through create/save, Graph selection, Field return, Study and Workbook, cold reopen, independent transfer, missing/changed source refusal, and installed-candidate acceptance. Existing [round-trip](../../../tests/e2e/scientific-cursor-graph-field.spec.ts), [Project return](../../../tests/e2e/graph-field-gf07.spec.ts), and [Study-pane](../../../tests/e2e/project-study-field-explorer.spec.ts) tests cover separate slices. See closure TODO #6a. | Start with one static analytic Field and a finite saved line on its declared plane. No general inverse Field reconstruction, arbitrary cross-document cursor map, or time-dependent trajectory claim. |

All four journeys are **release requirements**, not completed claims. A supported operation must say when its source is changed, missing, historical, or incompatible. No path may silently attach a result to a newer source or label producer success as independent mathematical verification.

## Other Gallery and module content

The 12 built-in Gallery Project routes are guided examples with saved Study/Note/Workbook narrative checks in the source tree. Their individual scientific operations remain qualified by each card and host; the 12/12 model matrix does not prove installed flagship journeys. The Volume → Mesh card opens a source-only Study; its extraction and two-pane Study require a current user run. The QWZ card participates in the flagship journey only after two verified external bundles are admitted. SSH and hydrogen are external-scene import entry points; the [Gallery matrix](CURATED_STUDY_GALLERY.md) records no bundled Study or verified producer fixture for either. The algebra card opens CAS examples and does not by itself prove a live Sage computation. The required Field journey has no dedicated Gallery card among the 16; provide a discoverable guided entry before publication, adding a card or replacing one deliberately.

Apart from the bounded Field route, the roadmap's suggested Green/Stokes, Fourier, Galois, broader vector-field flow, and other studies are **proposed catalogue content** without a completed flagship fixture and host receipt. [Volume → isosurface → Mesh](VOLUME_MESH_FIFTH_JOURNEY.md) has a Gallery entry and remains the leading fifth candidate (ACC-05), but it is **not a required 2.0 journey** while the mixed Mesh/Volume memory gate fails. Its bounded source contract, connected desktop flow, and release evidence are tracked separately. Reconsider promotion only after the memory gate passes and its source, threshold, retained Mesh, missing-resource, restart, and installed-host acceptance pass. Existing module tools and bounded `Open in…` routes should be described by their exact supported representation, mapping, and source requirements. Do not advertise a universal cross-module conversion, cursor, Inspector, visual Project relation map, or publication format until its acceptance case passes. These are scope limits, not permission to remove existing working functionality.

## Host claim for the candidate

| Host | 2.0 claim and disposition |
| --- | --- |
| Signed Windows desktop | **Primary GA host.** All four required journeys must pass on one exact signed installer and source commit. Core Geometry, Surface, Mesh, Graph and Project use must launch without a developer checkout or manually installed Python/Conda when the worker is advertised as bundled. Optional Sage and external QWZ producer routes must report absence honestly. |
| Local browser | Source-build evidence for documented Graph, Project, package and research-preview subsets. It is not an installed Windows receipt or a claim that desktop-only tools work in browser. |
| Hosted browser | Limited until deployment, storage, authenticated worker, external scene transport and failure-path receipts pass TODO #15–16. Do not advertise full 2.0 scientific parity. |
| Android | Limited or view-only by document, as stated in the [platform matrix](PLATFORM_CAPABILITIES.md). Physical-device and signed-artifact claims require TODO #17. No general Sage or desktop-native editor promise. |
| Linux packages | Limited until the exact package installation, runtime, Project reopen and bounded journey pass TODO #18. Do not infer support from a successful source build. |

The site currently labels its three original 2.0 workflows as targets and source-build views, and its capability page labels the published desktop download as 1.7.0. Add the required Field journey and its limits to the site and guided Gallery before publication. Compare every site, Gallery, help and download claim with the exact candidate and [platform matrix](PLATFORM_CAPABILITIES.md). P1 host work becomes a release blocker if that host is promoted as fully supported.

## Open-item disposition for release planning

The [defect and claim register](DEFECT_DISPOSITION.md) records each documented open failure and acceptance gap with an owner, affected journey, reproduction or evidence, source identity, and closure condition. The summary below is the release claim boundary.

| Item | Disposition | Closure or claim boundary |
| --- | --- | --- |
| Retained App contexts and mixed Mesh/Volume growth; failed 800-switch review | **Blocking** | Pass the clean 800-switch budgets and two-hour source plateau, then installed memory and viewer-disposal budgets on the exact candidate. TODO #2–3, #10, #14. |
| Four required journeys and live producer/runtime evidence | **Blocking for the flagship claim** | Qualify the four paths on the same reviewed commit, including their negative cases and independent fixtures. The Field Study/Workbook and exact-return route is a separate blocking acceptance case. TODO #4–6a, #9. |
| Windows signing, red Installer Smoke, exact candidate, clean install, upgrade and rollback | **Blocking** | Provision trusted signing, keep the release gate fail-closed, produce one manifest and prove the exact installed bytes and 1.7 data preservation. TODO #7–8, #11–13. |
| RC1 freeze, RC2 soak, signed-asset and SBOM integrity, Gallery media, GA audit | **Blocking for Windows GA** | Re-freeze after code and scope settle; bind the signed assets, installed captures, and uploaded bytes to the same reviewed identity. TODO #9–11, #19–20. |
| Optional native CGAL source and binary chain | **Blocking if the native binary is bundled or advertised** | Qualify matching source, build, license and SBOM ownership before inclusion; otherwise keep the optional backend absent. |
| Surface sampled ridge, QWZ producer samples, bounded CAS locus, optional runtimes | **Limited capability** | Keep the scientific and runtime qualifications visible in the app, documentation, Gallery and exports. A limitation cannot excuse stale or falsely verified values. |
| Hosted browser, Android device and Linux installed paths | **Limited host claim pending evidence** | Preserve the current restricted matrix. Promote a host only after TODO #15–18 and then treat its failed gate as blocking. |
| SSH and hydrogen linked Studies; additional suggested Gallery and algebra demonstrations; unrestricted cross-module maps | **Outside the proposed flagship claim** | Retain truthful import/preview paths where supported. Do not represent these as completed 2.0 end-to-end journeys without explicit scope expansion and acceptance. |
