## What counts as a journey

The roadmap originally defines **three flagship end-to-end journeys**: Surface, QWZ, and Algebra. The 2.0 scope adds **Field Explorer → Graph → Field** as a fourth required bounded journey. The [Guided Study Gallery](CURATED_STUDY_GALLERY.md) has **15 entry cards**, of which 11 create built-in Project copies, three require external scientific scene bundles, and one opens CAS examples. The [cross-module acceptance matrix](ROADMAP.md#19-cross-module-acceptance-matrix) has **16 cases**, including Field → Graph → Field as ACC-03. These counts describe a release promise, a catalogue, and an acceptance inventory respectively; one card or passing source test is not a complete end-to-end journey.

### Four required 2.0 journeys

| Journey | Claim within 2.0 scope | Required closure evidence | Explicit limit |
| --- | --- | --- | --- |
| Surface → Curve → Mesh → comparison → Workbook | A saved Surface yields a sampled characteristic Curve and tessellated Mesh; qualified analytic and discrete curvature evidence, its source relation, Study, and Workbook citation survive reopen and transfer. | Native desktop route through the exact saved sources; valid, changed, missing, cancelled and reimported cases; mathematical truth fixture; installed-candidate journey. See closure TODO #4. | A sampled interior curvature maximum and local discrete error are not a certified continuous ridge or convergence proof. Broader Surface families require their own evidence. |
| QWZ Study → reciprocal selection → Graph → publication | Two verified producer scenes form a four-view Study. A pinned reciprocal sample links the views and a bounded producer-sample path or section becomes a source-linked Graph and evidence export. | Independently verified scene bundles; exact reciprocal frame and sample checks; source-and-back navigation, cold reopen, tampered/missing source refusal, independent package transfer, and installed-candidate journey. See TODO #5. | External producer data is required. Connecting its samples does not compute new band energies or independently certify the physical model. |
| CAS polynomial/ideal → locus → Geometry/Curve → singularities | A supported Sage operation is admitted for a current typed algebra source; exact equations and bounded real visualization remain distinct, with saved singularity evidence and offline read-only reopen. | Live qualified Sage route, valid/cancelled/offline/stale/reimported cases, exact source and output identity, and installed-candidate route availability. See TODO #6. | The demonstrated path is bounded. Unsupported singular sets and general algebraic visualization are not claimed. Sage computation is optional when no qualified route is available; saved verified bytes remain readable. |
| Field Explorer → saved line profile → Graph → exact Field return | A finite, source-linked line profile from a declared physical plane becomes a saved Graph. A selected Graph row returns to its exact Field source and position; a Project Study and Workbook cite the verified source and result. | One connected desktop journey through create/save, Graph selection, Field return, Study and Workbook, cold reopen, independent transfer, missing/changed source refusal, and installed-candidate acceptance. Existing [round-trip](../../../tests/e2e/scientific-cursor-graph-field.spec.ts), [Project return](../../../tests/e2e/graph-field-gf07.spec.ts), and [Study-pane](../../../tests/e2e/project-study-field-explorer.spec.ts) tests cover separate slices. See closure TODO #6a. | Start with one static analytic Field and a finite saved line on its declared plane. No general inverse Field reconstruction, arbitrary cross-document cursor map, or time-dependent trajectory claim. |

All four journeys are **release requirements**, not completed claims. A supported operation must say when its source is changed, missing, historical, or incompatible. No path may silently attach a result to a newer source or label producer success as independent mathematical verification.

## Other Gallery and module content

The 11 built-in Gallery Project routes are guided examples with saved Study/Note/Workbook narrative checks in the source tree. Their individual scientific operations remain qualified by each card and host; the 11/11 model matrix does not prove 11 installed flagship journeys. The QWZ card participates in the flagship journey only after two verified external bundles are admitted. SSH and hydrogen are external-scene import entry points; the [Gallery matrix](CURATED_STUDY_GALLERY.md) records no bundled Study or verified producer fixture for either. The algebra card opens CAS examples and does not by itself prove a live Sage computation. The required Field journey has no dedicated Gallery card among the 15; provide a discoverable guided entry before publication, adding a card or replacing one deliberately.

Apart from the bounded Field route, the roadmap's suggested Green/Stokes, Fourier, Galois, broader vector-field flow, Volume→Mesh, and other studies are **proposed catalogue content** without a completed flagship fixture and host receipt. Volume → isosurface → Mesh is the leading fifth candidate (ACC-05), but it is **not a required 2.0 journey** while the mixed Mesh/Volume memory gate fails. Reconsider it only after that gate passes and its source, threshold, retained Mesh, missing-resource, restart, and installed-host acceptance can be scoped. Existing module tools and bounded `Open in…` routes should be described by their exact supported representation, mapping, and source requirements. Do not advertise a universal cross-module conversion, cursor, Inspector, visual Project relation map, or publication format until its acceptance case passes. These are scope limits, not permission to remove existing working functionality.

The site source now labels all four 2.0 workflows as targets and distinguishes source-build views from installed captures; its capability page labels the published desktop download as 1.7.0. Add the required Field journey and its limits to the guided Gallery before publication. Compare every site, Gallery, help and download claim with the exact candidate and [platform matrix](PLATFORM_CAPABILITIES.md). P1 host work becomes a release blocker if that host is promoted as fully supported.
