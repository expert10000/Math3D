# M3D20-16 — RC1 freeze preparation

RC1 has **not** been declared. The root app, desktop workspace, renderer and both npm lockfiles now identify 2.0.0. The source baseline still needs the recovery and soak gates, a signed candidate and installed qualification before release signoff. The freeze verifier prevents a later RC1 from being declared from a loosely identified branch or drifting dependency, schema and native-source inputs.

After the 2.0 integration baseline is reviewed, branch from that exact commit. Store the freeze manifest outside the checkout; `node scripts/prepare-release20-freeze.mjs <new-manifest>` creates and self-checks one from a clean commit, and `node scripts/verify-release20-freeze.mjs <freeze-manifest>` verifies it again. The command requires manifest source commit equal to `HEAD` and version 2.0.0 in root, desktop, renderer and both npm lockfiles. It checks exact SHA-256 bytes of both npm lockfiles and the frozen worker/runtime requirements, exact resolved Electron, electron-builder, and better-sqlite3 versions, the known Project, mixed-workspace, and saved-result contracts, and the Windows native corresponding-source inventory. The standalone native CGAL worker remains excluded from the installer while its distribution gate is blocked.

The candidate workflow requires the independently reviewed freeze manifest SHA-256 as a dispatch input. It regenerates the manifest from its checkout and refuses a different digest before packaging. Generating a manifest alone does not approve a release or sign an installer.

The manifest shape is `math3d/release20-rc1-freeze/v1` with `status: "frozen"`, `version: "2.0.0"`, a full `sourceCommit`, and maps named `lockfiles`, `dependencies`, `contracts`, and `nativeSources`. Each `lockfiles` entry maps the required relative path to its SHA-256. Each `contracts` entry holds `sha256`, `format` (or `null` for analysis results), and `schemaVersion`. `nativeSources` pins the dependency and public-source manifest bytes, native CGAL 6.2 source hash, and blocked packaging status. The verifier requires exact key sets; it refuses missing or extra entries. Re-run it after any dependency, schema or source edit. Any drift needs a new reviewed baseline and manifest.

The freeze check is one prerequisite. The combined source matrix includes mobile Study and desktop Field Explorer Study checks, but a manifest alone does not prove their installed behavior, the open navigation memory plateau, full CI, mathematical fixtures, installer, migration, website captures, or release signoff. The [RC1 acceptance gate](RC1_ACCEPTANCE_GATE.md) records those separately. The fixture test `node scripts/test-release20-freeze.mjs` checks a synthetic 2.0 baseline and rejects lockfile drift and a 1.7 version.
