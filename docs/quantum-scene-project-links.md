# Quantum scenes in saved Math3D Projects

## Desktop walkthrough (M3D-Q09)

1. In Theory Lab, open a compatible saved run in **Scenes**, select its scene view, then choose **Open in Math3D**. Theory Lab exports a portable `.qscene` bundle and launches Math3D with `--quantum-scene <bundle folder>`. To import an existing bundle manually, use Math3D **File → Open Theory Lab quantum scene (.qscene)** and choose the `.qscene` **folder**, not `manifest.json` or `bundle.json`. The pinned **File → Verified quantum examples** use the same importer.
2. Inspect the verified scene and its source/provenance in the read-only viewer. Close the viewer, open **Projects**, and use **Attach open verified scene** in Contents (or the **Verified scene links** card's **Manage links / attach in Contents** shortcut). Choose **Save project**. Attachment alone is not a save.
3. After a restart, open the saved Project, then choose **Verify and view scene**. If the external bundle is absent or changed, a link-only Project can still open, but the scene is marked unavailable and no preview is shown. Use **Relink source** to select an exact-hash copy of the original bundle and **Save changes**. An admitted read-only Project document has stricter activation checks: it cannot activate from a stale source.

The desktop picker, pinned example, and Theory Lab-style `--quantum-scene` launch have a parity test against the same pinned QWZ bundle. A separate live Windows test starts Theory Lab, computes a real Rabi run, clicks **Open in Math3D**, verifies the launched Math3D process accepted the exact Lab-created bundle, then confirms the startup and manual-import routes produce one canonical Math3D document. It also checks Theory Lab's **Export scene bundle → Open scene bundle → Open in Math3D** path against those same bytes. Malformed launch folders produce a visible, one-shot refusal. Project restart tests cover changed-source refusal and exact-fingerprint relinking.

To rerun the desktop acceptance, build both checkouts, set `QLAB_E2E_CHECKOUT` to the absolute Theory Lab checkout path, then run `npm run test:quantum:q09` from Math3D. The live test uses isolated profiles and cleans up its own receiver processes; without that variable it is explicitly skipped while the four self-contained Q09 tests still run. No OS file association or URL/deep-link transport is used or claimed by this handoff.

Math3D Projects can retain a `quantum-scene/v1` or `quantum-scene/v2` source as a sealed, external, read-only link. The Project envelope stores a title, bundle directory and 64-character scene fingerprint under `quantumScenes`. Its structural hash covers these references. Existing Project revisions without this optional field remain valid.

The Project contents panel offers **Attach open verified scene** after a desktop scene has been opened. Attachment re-verifies the source and remains staged until **Save project**. **Verify and view scene** reopens through the existing Electron quantum-scene importer, which checks the bundle manifest and datasets before showing the existing geometry, field-slice or density-surface preview. If the directory is absent or bytes have changed, the Project stays intact and the scene is unavailable; no unverified visualization is shown.

The **Verified scene links** card near the top of the Project panel shows linked scene titles and provides one-click re-verification and preview. Its separate **Open .qscene folder** and **Open .sscene folder** buttons use the corresponding native importers; neither action attaches automatically. **Manage links / attach in Contents** jumps to the full lists, where attachment and exact-source relinking remain available. The same two formats have distinct File-menu commands.

The link can remain link-only, or **Add read-only Project document** can admit it into the mixed-workspace graph as `math3d.quantum-scene-document`. This compact document records the immutable scientific descriptors and fingerprint, with the local bundle folder stored separately. It appears in Project contents and opens in the same verified viewer. It is not a Geometry, Mesh or Volume document and cannot enter their source editors, analysis commands or kernel worker. Project JSON does not embed scene arrays. A portable Project can retain the reference on another machine, but its source must be present and verify at that directory before the document can open. The versioned Theory Lab → `quantum-scene/v1|v2` → Math3D boundary remains read-only; Math3D does not call the Theory Lab worker.

If the bundle moves, use **Relink source** in Project contents. The dedicated native folder picker verifies the complete replacement bundle and requires the exact same fingerprint; it does not alter the active scene or recent-scene shortcut. The Project link and admitted document location change together, while the document's scientific identity stays fixed. For an active Project, relinking is staged until **Save project**. For an imported saved preview, relinking atomically updates only the saved library copy, leaving the active workspace untouched; open that copy afterward. Cancellation, mismatch, corruption, or a failed save leave saved Project bytes intact. Saving, opening, navigating to the document, and opening the link each re-verify the source. Project activation refuses any mismatched descriptor before committing the workspace.
